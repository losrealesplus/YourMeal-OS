## ¿Qué es?

El hito en el que YourMeal OS **deja de comportarse como un proyecto cuyo objetivo es construir funcionalidades** y pasa a comportarse como **Implementación de Referencia (RI-001)**: un sistema cuyo objetivo es **demostrar que el modelo operacional sobrevive al uso real**.

Incluye la consolidación en `main` del modelo Party/B2B/B2C, los workspaces Cocina/Reparto, el checklist de aceptación del piloto y la formalización del **Gate G-02 · Pilot Readiness** (= Pilot Authorization ≠ Release), con el criterio **No Artificiality**.

## ¿Cómo es?

```text
Antes:  Construir YourMeal OS
Ahora:  Demostrar que el modelo operacional funciona en operación real
```

Separación de demanda (canónica):

```text
Party
├── Individual Customer          → CJ-001 · B2C
└── Company
      ├── Site
      ├── Organizational Unit
      ├── Employee Membership    → vínculo por Company Code
      └── Delivery Group
```

Flujo comercial: EatClean **crea** empresas; empleados **solo se vinculan**; particulares mantienen CJ-001.

Journey operativo mínimo cerrado:

```text
Cliente → Onboarding → Pedido → Centro de Operaciones
  → Cocina → Preparación → Reparto → Entrega → Pedido cerrado
```

Niveles de conocimiento (no “fases de desarrollo”):

```text
FOUNDATION … IOV · FOV PREPARATION · ORR (marco) · G-02 (definido)  ✅
────────────────
Siguiente: PILOT (RI-001) → Evidence → Knowledge Update
```

## ¿Por qué existe?

Porque FOPEBA no certifica productos por cantidad de módulos. Certifica que hay **integridad del Operational Journey** y **incertidumbre explícita** antes de exponer el modelo a la realidad.

Sin este hito, el equipo seguiría preguntando *«¿qué feature añadimos?»* en lugar de *«¿qué nos enseña la operación?»* — y RI-001 no tendría valor como contribución de conocimiento al framework.

## ¿Para qué sirve?

1. **Autorizar** (tras firmar checklist + ORR) el inicio de Validación Operacional vía **G-02**.  
2. **Proteger** la evidencia con **No Artificiality** (sin SQL silencioso, bypass ni datos inventados).  
3. **Clasificar** el trabajo posterior como Evidence / KU / Correction / Pilot Fix / Operational Finding.  
4. **Congelar** la apertura de módulos de arquitectura: el siguiente artefacto es **evidencia**, no un PR estructural.
