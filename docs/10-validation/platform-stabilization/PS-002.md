## Objetivo

Demostrar que el **contrato canónico post-login** se cumple de extremo a extremo — no basta con “se navega”.

### Condiciones adicionales

1. **No aparece ningún `getSession()` inmediato** después del login (`signInWithPassword` / `signUp` / `verifyOtp` → bootstrap). Cold-start `getSession` al montar `/auth` sigue permitido.
2. **Cada evento del pipeline ocurre exactamente una vez** (sin duplicados, sin bucles).
3. Consola: prefijo `[FCR-008]` + `pipelineId`.

Implementación: `src/auth/post-login-pipeline.ts` · `validateCanonicalPipeline()`.

## Procedimiento PS-002-C (Auth real)

1. App **sin** `VITE_BOOTSTRAP_MODE` (Identity Provider = Supabase).
2. Abrir `/auth/admin` (Ops) o `/auth` (Customer) según el caso.
3. Login con credenciales reales Supabase.
4. Capturar logs `[FCR-008]` (DevTools / Playwright `page.on('console')`).
5. Ejecutar validación:

```ts
validateCanonicalPipeline(observedSteps)
// ok === true  ∧  duplicates === []  ∧  missing === []
```

6. Confirmar UI del dashboard destino (Ops `/admin*` o Customer `/app`).
7. Confirmar estáticamente: submit paths no llaman `getSession()` tras el auth API.
