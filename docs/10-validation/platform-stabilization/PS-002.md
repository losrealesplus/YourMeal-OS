### Forma del reporte (regresión comparable)

```json
{
  "status": "PASS | FAIL | BLOCKED",
  "reason": "",
  "pipeline": [],
  "duplicates": [],
  "missing": [],
  "out_of_order": [],
  "duration_ms": {
    "login_to_session": 87,
    "session_to_bootstrap": 24,
    "bootstrap_to_dashboard": 163
  },
  "code_status": "UNCHANGED"
}
```

| Status | Significado | Exit | Abrir FCR |
|--------|-------------|------|-----------|
| **PASS** | Pipeline completo correcto | 0 | No |
| **FAIL** | Pipeline empezó y se rompió en un paso | 1 | Sí — solo ese paso |
| **BLOCKED** | No pudo empezar (credenciales / server / env) | 2 | **No** |

`duration_ms` es **diagnóstico** (comparar regresiones futuras), no un umbral de rendimiento.  
`PS002_EMAIL` / `PS002_PASSWORD` forman parte del **contrato** del gate — no mockear Auth.

Validador unitario Node: `npm run test:canonical-pipeline`.
